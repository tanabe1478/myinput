# .claude/ - Development Memory

This directory contains development specifications and logs. **It is committed to git for traceability**.

## Purpose

This is your **external memory** for LLM-assisted development:
- **Specifications**: What you planned and what you actually built
- **Work Logs**: Investigations, trials, decisions, findings
- **Issues**: Task descriptions and context

## Structure

```
.claude/
├── issues/YYYY-MM/     # Task descriptions
│   └── <slug>-<id>.md
├── specs/YYYY-MM/      # Specifications (planned + as-built)
│   └── <slug>-<id>.md
├── log/YYYY-MM/        # Work logs and investigations
│   └── <slug>-<id>.md
└── templates/          # Templates for consistency
    ├── issue-template.md
    ├── spec-template.md
    └── log-template.md
```

## Naming Convention

**Format**: `<slug>-<id>.md`

- **slug**: English kebab-case (`auth-fix`, `api-refactor`, etc.)
- **id**: 6-8 digit lowercase hex (generated by LLM)
- **Example**: `auth-403-fix-9f3a7c.md`

## One Task = Three Files

For each task, create three files with the same `<slug>-<id>`:

1. **Issue** (`issues/YYYY-MM/<slug>-<id>.md`)
   - Task context and description
   - Links to related GitHub issues

2. **Spec** (`specs/YYYY-MM/<slug>-<id>.md`)
   - Planned design (before)
   - As-built reality (after) ← source of truth
   - Differences and design notes

3. **Log** (`log/YYYY-MM/<slug>-<id>.md`)
   - Session notes
   - Investigations and findings
   - Decisions and reasoning

## Usage

### Starting a Task (Gate A)
```bash
# LLM creates:
.claude/issues/2025-01/feature-name-a1b2c3.md
.claude/specs/2025-01/feature-name-a1b2c3.md  # Status: draft
.claude/log/2025-01/feature-name-a1b2c3.md
```

### During Work
- Append findings to log file
- Update spec if design changes

### Before PR (Gate B)
- Update spec's "As-Built" section
- Document differences from planned
- Change status to "implemented"

## Why Commit This?

- **Traceability**: Complete history of decisions and investigations
- **Team context**: Others can understand why and how decisions were made
- **Documentation**: Living record of implementation journey
- **Knowledge sharing**: Learning from past work
- **Audit trail**: Clear record for compliance and review

## Branch and PR Strategy

Every task follows this flow:
1. **Create branch**: `claude/<slug>-<id>`
2. **Commit .claude/ files**: Immediately after creation
3. **Implement changes**: Regular commits during work
4. **Update spec**: Fill As-Built section before PR
5. **Create PR**: Every task gets a PR, even small ones

## What Goes to Pull Requests?

Based on the updated As-Built spec:
- **Results**: What was implemented
- **Impact**: How it affects users/system
- **Verification**: Test coverage and validation
- **Why** (when needed): Complex decisions or tradeoffs
